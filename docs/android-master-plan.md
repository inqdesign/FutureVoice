## 일하는 규칙

1. **한 번에 한 항목.** 순서대로 한다. 다음 항목으로 넘어가기 전에 지금
   항목을 ☑로 만들거나, 막힌 이유를 적고 ⏸로 둔다.
2. **☑에는 증거가 붙는다.** 커밋 해시, 스크린샷 경로, 테스트 이름 중
   하나 이상. 증거 없는 ☑는 없다.
3. 작업 중 새로 찾은 문제는 **그 자리에서 고치지 않는다.** 알맞은 단계에
   항목으로 적고 원래 항목으로 돌아간다(치명적인 것만 예외, 예외도 적는다).
4. 항목을 끝낼 때마다 이 문서의 상태와 맨 아래 진행 기록을 갱신하고
   같은 커밋에 넣는다.

### 따라잡은 뒤의 방식 (2026-09-21 결정)

- **따라잡기는 이번 한 번.** 이 문서가 끝나면 안드로이드가 기준 빌드와 같다.
- 그 뒤로 **개인정보·돈·학습 루프에 닿는 iOS 기능은 같은 세션에서 안드로이드
  까지 같이 넣는다.** 순수 화면 다듬기는 iOS 커밋 메시지 끝에 `Android:` 한
  줄(옮길 것 한 줄 요약, 또는 `n/a`)을 붙이고, 릴리스마다
  `scripts/android/ios-delta.sh <이전 릴리스> <새 릴리스>`가 옮길 목록을 뽑는다.
- 계산 규칙은 iOS 테스트가 쓴 정답 파일을 안드로이드 테스트가 읽는다(1.4) —
  iOS에서 규칙이 바뀌면 안드로이드가 자동으로 빨개진다.

상태: ☐ 안 함 · ◐ 진행 중 · ☑ 끝(증거 있음) · ⏸ 막힘(이유 있음)

## 완료 기준 — "어느 정도 수준"의 정의

기준선은 다섯 가지다. 갤러리의 **모든 화면**이 이걸 넘어야 한다.

1. 죽지 않는다 (logcat에 FATAL 없음)
2. 한국어 모드에서 영어가 새지 않는다 (의도된 영어 — 학습 자료, 하루
   카드 — 는 목록으로 예외 처리)
3. 시스템 바·키보드에 가려지거나 잘린 조작 요소가 없다
4. iOS 같은 화면과 나란히 놓고 사장님이 "다르다"고 짚은 곳이 없다
5. 규칙 테스트(5단계)가 전부 초록이다

## 1단계 · 검수 장치 — 매번 다시 돌릴 수 있게

이게 없으면 확인이 수작업이고, 한 번 맞춘 화면이 다시 깨져도 모른다.

- ☑ **1.1 캡처 장치** — 디버그 계열에서 `--es capture <모드>`로 어떤 화면이든
  샘플 데이터로 바로 띄운다. 모드 이름은 iOS와 똑같이(빌드 54 기준 103개).
  - ☑ 1.1a 뼈대 — `capture` 빌드 타입(`.capture`, 개발 앱 옆에 따로 깔려
    실제 계정 데이터를 건드리지 않는다), iOS 모드 103개 등록, 아직 안 이은
    모드는 빨간 "NOT WIRED" 화면(갤러리가 빈 곳을 숨기지 않게), `--es lang ko`
    언어 지정, `scripts/android/emu-up.sh`.
    실행: `adb shell am start -n com.roro.futurevoice.capture/com.roro.futurevoice.MainActivity --es capture paywall --es lang ko`
  - ☑ 1.1b 샘플 데이터 — iOS 하니스의 시드 8개와 샘플 계정·영수증을 같은
    값으로(`CaptureSeed.kt`, `--es seed all`). 다시 실행해도 쌓이지 않게 id를
    내용에서 만든다. **옮기지 못한 것은 안드로이드에 그 필드가 없어서이고,
    전부 기존 항목에 걸려 있다:** 기억 줄의 공개 단계·근거(→ 2.1), 알던
    단어·표현의 사용 확인(→ 2.20), 갱신 정보(→ 2.18).
  - ☑ 1.1c 모드 잇기 — **103개 전부: 실제 화면 82, NOT PORTED 21, 못 이은 것 0.**
    한국어로 한 바퀴 돌려 크래시 0, 빈 화면 0(`scripts/android/capture-sweep.sh`).
    화면 훅은 `capture/flags/*CaptureFlags.kt`에만 있고 보통 빌드에선 전부 꺼져
    있다. NOT PORTED 21개는 모두 플랜 항목을 가리킨다: 일본어 4(2.15), 공개
    소개·기억 2(2.1), 무료 10분 안내(2.16), 동기화(2.28), 위젯 5(4.7), 항목별
    복습 알림 2(4.8), 레벨 시트(4.3), 통화 중 크레딧 줄(4.6), 사람 추가 인터뷰
    (4.12), iOS가 출시하지 않은 실험 화면 3(해당 없음).
- ☑ **1.2 갤러리** — `scripts/android/gallery.sh <폴더> [ko|en] [light|dark]`가
  iOS(기준 빌드를 따로 빌드해 **갤러리 전용 시뮬레이터**에 설치 — 다른
  세션의 시뮬레이터는 건드리지 않는다)와 안드로이드 캡처 앱에서 모든 모드를
  찍어 한 페이지로 만든다. 문제 있는 모드가 위로 오고, 판정(화면 / 앱에 없음 /
  못 이음 / 크래시 / 빈 화면)으로 거를 수 있다. 첫 실행(한국어·라이트):
  화면 82 · 앱에 없음 21 · 크래시 0 · 빈 화면 0. 페이지:
  https://claude.ai/artifact/Hsf8SDVXoEUb8Muy1W9kFy
  - 빈 화면 판정은 가운데를 뺀 곳에 글자 픽셀이 있는지로 한다 — 색 격자로
    보면 흰 바탕이 넓은 진짜 화면 23개가 빈 화면으로 잘못 나왔다.
- ☑ **1.3 자동 판정** — `scripts/android/ui_checks.py`. 스윕이 모드마다 뷰
  트리(uiautomator)와 시스템 바 위치를 같이 저장하고, 갤러리가 "문제 있음"으로
  표시한다:
  - **영어가 샘** — 화면 글자가 카탈로그 문자열의 영어 원문과 정확히 같고 그
    문자열에 번역이 있을 때(학습 자료는 카탈로그와 겹치지 않아 걸리지 않는다)
  - **빈 자리표시** — `%s`·`%1$d`·`%lld`·`{name}`가 화면에 나옴
  - **시스템 바에 가림** — 누를 수 있는 요소가 상태 바·내비게이션 바와 겹침
  - **화면 밖 글자** — 오른쪽 끝을 넘어 배치된 글자
  - **코드에 박힌 영어**(정적) — 컴포저블에 직접 쓴 영어 문구. 런타임 검사는
    카탈로그에 없는 문구를 못 보므로 소스를 따로 읽는다.
  - **못 보는 것:** 상자 안에서 잘린 글자(뷰 트리는 전체 문자열을 준다) — 사람이
    갤러리에서 본다.
  시험: 네 모드에서 이미 아는 결함 둘(4.13·4.14)을 스스로 잡았고, 가짜 트리로
  가림·영어·화면 밖 세 가지가 다 걸리는 것을 확인했다.
- ☑ **1.4 규칙 테스트 틀** — 이미 있던 장치(`gen-vectors.sh`: 진짜 Swift 코드를
  컴파일해 입력·정답 JSON을 쓰고, JUnit이 같은 파일을 읽는다)를 빌드 54로
  되살렸다. 빌드 54의 Swift가 새로 끌어오는 `WordSplitter`·`JapaneseMorph`를
  넣고, iCloud 동기화 훅은 빈 껍데기로 막았다. 한 명령으로:
  `scripts/android/rules-check.sh` — 벡터를 다시 쓰고, **바뀌었으면 "iOS 규칙이
  움직였다"고 알리고**, 안드로이드 테스트를 돌린다. 현재 10개 초록(섀도잉 점수,
  요약 흡수 9). 5단계는 이 틀에 규칙을 하나씩 더하는 일이다.
- ☑ **1.6 문자열 이름 고정** — 이름을 한 번 정하면 `scripts/android/string-names.json`
  장부에 남기고 다시는 바꾸지 않는다. 새 키만 이름을 받는다(아무도 쓴 적 없는
  이름이면 그대로, 아니면 해시 꼬리). 사라진 키도 장부에 남아 그 이름이 다른
  문장에 넘어가지 않는다. 오늘 이름으로 장부를 채웠고, 생성 결과는 한 글자도
  바뀌지 않았다.
- ☑ **1.5 흐름 스모크** — `scripts/android/smoke.py`. 로그인된 개발 앱에서 실행 →
  대화 홈 → 통화 열고 말하기 전에 끊기 → 연습 탭 → 책 열기 → 문장 덱에서
  카드 한 장 넘기기 → 성장 탭. 한 단계라도 도착하지 않거나 앱이 죽으면 멈춘다.
  **마무리 화면은 뺐다** — 학습자가 말한 턴이 있어야 하는데 에뮬레이터 마이크는
  잡음이라, 돌리면 진짜 초가 과금되고 진짜 요약이 써진다. 6단계(실기기)에 있다.
  첫 실행 6/6.

**1단계 끝.** 이제 검수 장치 다섯 개가 한 줄씩이다: `emu-up.sh` ·
`capture-sweep.sh` · `gallery.sh` · `rules-check.sh` · `smoke.py`.

## 2단계 · 빌드 44 → 54에서 iOS에 들어온 것

안드로이드는 빌드 44를 기준으로 옮겼다. 그 뒤 빌드 54까지 iOS에 들어온
사용자 쪽 변경(게이트웨이·어드민·번역 커밋 제외)을 하나씩 확인한다.
"있음"이 아니라 **iOS와 같게 동작함**이 확인 기준이다.

- ☑ **2.1 공개 소개 동의와 기억의 공개 단계** (`9209a63`, `e00a27a`) — **실제로 새고
  있었다**: 안드로이드는 켤 때마다 확인 없이 소개를 올렸고 가족·자유 메모까지
  넣었다(테스트 계정 행이 프로덕션 공개 풀에 떠 있음 — 7.6). 이제 본인이 문단을
  한 번 보고 고르기 전엔 아무것도 올리지 않는다(공개 / 먼저 고치기 / 나중에 —
  나중에는 이전 빌드가 올린 행을 내린다). 소개문은 iOS와 같은 재료만(직업·도시와
  기간·상황·허락된 기억). 기억 줄은 비공개·대략만·공개 세 단계와 근거("…라고
  말했어요")를 갖고, 모르는 사람 쪽(소개문, 사람 찾기의 상대 역할 프롬프트)은
  허락된 단계만 읽는다. 옛 파일은 느슨하게 읽는다(모르면 비공개). 프로필에 기억
  목록·단계 바꾸기·"이제 끝난 일"·소개문 실시간 미리보기. 테스트 16개, 캡처
  `intro-preview`·`profile-notes` 연결.
  **남은 것 → 2.29:** 안드로이드 요약은 서버 함수라 새 기억 필드를 아직 안 준다.
- ☑ **2.2 책은 챕터를 다 해야 끝난다** (`29c8fe5`) — 스냅샷이 단어·표현·섀도잉·교정
  넷이 되고 전부 진도에 들어간다. 요약의 교정(`phrasesUsed`)도 이제 센다(같은
  문장은 한 번). 책 페이지는 스냅샷을 그대로 그리고, 네 리본 모두 완료/전체를
  단다. `shadowLineId`→`correctionId`, 일본어 문장 끝(。！？)으로도 자른다.
  테스트 7개(단어만 끝내선 책이 안 끝남 포함), 캡처로 iOS와 챕터 수 대조(표현 4·
  섀도잉 1·드릴 3 일치). 단어 수 차이(iOS 5, 안드로이드 3)는 목록 밖 단어라
  2.4 몫. 드릴 페이지 모양은 4.17, 버린 표현은 4.18.
- ☑ **2.3 문장 카드 "알아요"는 은퇴** (`1ab175d`) — 최상단 칸의 복귀일을 없앴다
  (`RETIRED_REVIEW_AT`). 옛 규칙으로 5칸에 있던 카드는 읽는 순간 은퇴하고, 미루기는
  최상단에 못 올라가며, 알림은 은퇴 카드를 건너뛴다. 은퇴한 카드는 덱의 **아는 것
  폴더에 남고**(안드로이드는 아예 빼고 있었다 — 이제 iOS처럼 GOT_IT로 묶고, 그 안엔
  복귀 시각 대신 "아는 것으로 표시함"), 거기서 다시 파일링하면 돌아온다. 테스트 4개,
  캡처로 칩 수가 iOS와 같음 확인(2·2·2·2).
- ☑ **2.4 통화가 가르친 단어는 저절로 공책에** (`7f6f5ec`) — 요약이 끝나면 그 통화가
  가르친 단어가 공책에 들어간다(`keepFromTalk`, 책 단어 챕터와 **같은 집합**,
  `addStudying` 반복 아님 — 연습 횟수도 `word_saved`도 안 남는다). 손으로 뺀 단어는
  `vocab_removed_by_hand.json`에 남아 다시 안 들어가고, 다시 북마크하면 그 표시가
  지워진다(졸업은 `byHand = false`). 같은 커밋의 나머지 둘도 같이: 등급 목록에 없는
  단어도 미래의 나의 말에서 걷고(여러 턴에 나온 것 먼저, 상한 없음), 학습자가 그
  통화에서 쓴 단어는 빼놓는다(`excludingLemmas`). 테스트 7개.
  **안드로이드만의 차이 둘**: 품사 태거가 없어 닫힌 품사는 손으로 적은 목록
  (`CoreVocabulary.isUngraded`)이 대신한다 — iOS는 43개, 여기는 ~230개;
  그리고 표제어 환원이 없어 불규칙형("took", "mattered")이 한둘 새어 들어온다
  (`VocabLemmas`가 표면형이라는 기존 격차, 4.20).
- ☑ **2.5 의견은 돌아온 통화 뒤 한 번** (`f82c229`) — 묻는 자리는 확인 완료: 세 조건
  (1분 이상·두 번째 이상으로 끝낸 통화·첫 통화가 오늘이 아님), 평생 한 번, 별점 둘
  (앱·통화)에 글만 써도 보내짐, `call_rating`·`app_version`·`app_build`까지 같은 모양.
